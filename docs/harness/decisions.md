# Decisions

확정되어 재논의 대상이 아닌 사항. 새 결정은 append.

- **사이트 범위**: ConnectX 통합 1개 사이트, Academy/Advisory/Wellness는
  하위 섹션/페이지(`/academy`, `/advisory`, `/wellness`)로 구성. (2026-08-18)
- **기술 스택**: Next.js (App Router) + TypeScript + Tailwind CSS, npm.
  (2026-08-18)
- **marketing-lead 역할**: 사이트 기획/정보구조/카피 방향만 담당. 코드·비주얼
  구현에는 관여하지 않음. (2026-08-18)
- **협업 방식**: Codex와 Claude Code는 별도 CLI 세션이라 실시간 통신이
  불가능하므로 `docs/harness/` 공유 문서로 조정. (2026-08-18)
- **톤앤매너**: 전문적/신뢰감 우선. Advisory의 B2B 포지셔닝(SMB Infra &
  Security Transformation Partner)을 고려한 톤을 전체 사이트 기본값으로 삼음.
  (2026-08-18)
- **호스팅**: GitHub Pages (정적 export, `output: "export"`) + 가비아에서
  구매한 connectx.kr 커스텀 도메인. `.github/workflows/deploy.yml`이 main
  push마다 자동 빌드/배포. (2026-08-18)
- **이미지 제작 담당 분리**: Claude Code(개발/디자인팀장)는 코드로 직접 그리는
  벡터(SVG) 그래픽까지만 담당하고, 사진/AI 생성 이미지 등 래스터 이미지
  제작은 Codex(CTO)가 담당하기로 함. 이유: Claude Code에는 이미지 생성
  도구가 없고, 사용자가 "텍스트 위주라 단조롭다"는 피드백을 반복해서
  SVG 일러스트만으로는 부족하다고 판단, 사용자가 직접 역할 분리를 요청함.
  (2026-08-18)
- **npm audit 취약점(5건, 전부 high) 방치 결정**: 전부 `next` 14.2.35 →
  16.3.1(메이저 2단계) 강제 업그레이드로만 해결 가능. 취약점 내용(Server
  Actions DoS, Middleware SSRF, RSC 캐시 오염 등)은 전부 Next.js를
  self-host 서버로 돌릴 때 해당하는 이슈이며, 이 사이트는 정적 export만
  배포하므로 실질적 노출 없음. postcss/glob 취약점도 빌드 시점 전용 도구라
  공격 경로 없음. 따라서 지금 강제 업그레이드로 빌드를 깨뜨릴 위험을
  감수하지 않고 방치하기로 결정. Next 16 업그레이드는 나중에 별도
  작업으로, 충분히 테스트하며 진행할 것. (2026-08-18)
- **Advisory 대표 서비스명 변경**: 기존 "외부 기술기획실"을 Hero eyebrow/
  positionDetail 제목 등 주요 식별 위치의 대표 명칭에서 내리고, "IT
  인프라·보안 자문"을 대표 서비스명으로 승격. "외부 기술기획실"은 본문 내
  보조 비유 표현으로만 유지. 브랜드 H1("ConnectX Advisory")과 영문
  포지션뱃지는 유지하되, 영문 뱃지 문구는 "SMB Infra & Security
  Transformation Partner"에서 "중소기업을 위한 IT 인프라·보안 파트너"로
  한국어화. 위 2026-08-18 톤앤매너 결정에 언급된 영문 포지셔닝 문구를
  대체하는 결정. 근거: 외부 UX 감사 보고서(OpenAI Astra 진단,
  `ConnectX_홈페이지_UX_검토보고서_20260930.md`, 사용자가 직접 첨부)가
  "외부 기술기획실"은 기억엔 남지만 서비스 범위(제품 개발까지 하는지,
  상주하는지 등)가 모호하다고 지적, 사용자에게 직접 확인 후 리포트
  권장안대로 반영하기로 확정. (2026-09-30)
- **mailto 기반 신청 방식 유지 결정**: 위 UX 감사 보고서는 "사이트 안에서
  신청 완료를 확인할 수 있는 문의 폼"을 최우선 개선 항목으로 권장했으나,
  이 사이트는 GitHub Pages 정적 export라 서버가 없어 실제 폼을 만들려면
  Formspree 등 외부 제출 서비스 연동(가입, 무료 티어 제한)이 필요함. 이
  비용/의존성을 감수하지 않고 기존 mailto 방식(2026-09-29 도입)을
  그대로 유지하기로 사용자가 확인. 추후 실제 폼 도입을 원하면 이 결정을
  재논의할 것. (2026-09-30)
- **npm audit 취약점 재검토 (v1.0 push 시 GitHub이 31건 경고) — 방치 결정
  유지**: `npm audit`으로 직접 확인한 결과 실제로는 7개 패키지 그룹(6
  high + 1 critical), 개별 CVE 기준으로는 약 40건으로 GitHub Dependabot이
  세분화해서 보여주는 "31건"과 같은 근본 원인 집합임을 확인 — 2026-08-18에
  이미 검토/방치를 결정한 `next`(14.2.35→16.3.7 필요)와 `postcss`/`glob`에
  더해 `js-yaml`, `brace-expansion`이 새로 이름이 붙었지만, 둘 다
  `eslint`/`eslint-config-next`의 개발용 전이 의존성(빌드/린트 시점에만
  실행, 배포되는 정적 사이트 번들에는 포함 안 됨)이라 동일한 논리로 실질
  노출 없음. `next` 항목에 RCE(Remote Code Execution) 등급 취약점 2건이
  새로 포함되어 있었으나 전부 self-host 서버(Server Actions, Image
  Optimization API, Windows 서버 등)에서만 발동하는 이슈이고, 이 사이트는
  `next.config.mjs`의 `output: "export"`로 정적 HTML만 생성해 GitHub
  Pages가 서빙하므로 Next.js 서버 프로세스 자체가 존재하지 않아 해당
  공격면이 없음. 따라서 기존 방치 결정을 그대로 유지. Next 16 업그레이드는
  여전히 별도 작업으로 남겨둠. (2026-09-30)
- **콘텐츠 갭(실데이터 없음) 처리 원칙**: 커리큘럼 세부사항, 자문 SLA,
  전문가 검증 체계 등 사업 측 확정 데이터가 없는 항목을 채울 때는 두
  극단을 피한다 — (1) 근거 없는 권위 주장("전문가가 검수한")을 사실처럼
  단정하지 않고, 법적 표시기준·원료·소비기한 등 누구나 확인 가능한 구체
  기준으로 대체한다. (2) 수치가 필요한 경우(교육 기간, 자문 미팅 횟수
  등)에는 그럴듯한 예시 값을 "예시이며 상담/계약 시 확정" 같은 명시적
  단서와 함께 제시한다. 완전히 모호하게 비워두거나, 반대로 확정된 사실인
  것처럼 꾸며내는 것 둘 다 하지 않는다. 근거: 2026-09-30 UX 감사 반영 때
  Wellness의 "전문가가 검수한 제품만 소개합니다" 류 표현이 근거 없는
  권위 주장으로 지적되었고, 이를 대체할 때 적용한 원칙을 이후 콘텐츠
  갭 보강 작업 전반(Academy 커리큘럼, Advisory SLA)에도 동일하게
  적용하면서 재사용 가능한 원칙으로 확정. (2026-10-01)
