# ConnectX 홈페이지 UX 검토 보고서

- 검토 대상: https://www.connectx.kr/
- 검토일: 2026년 9월 30일
- 검토 페이지: 홈, Academy, Advisory, Wellness
- 검토 관점: 정보 구조, 서비스 이해도, UX 라이팅, 시각적 가독성, 문의·구매 전환 경로
- 작성 기준: 앞서 실제 홈페이지를 열어 확인한 화면·문구·링크와 이에 대한 개선 의견을 정리했습니다. 이후 변경된 사이트 상태를 재검토한 문서는 아닙니다.
- 검토 범위: 데스크톱 공개 화면과 주요 링크·FAQ. 모바일 실기기 테스트, 실제 방문자 행동 분석, 성능·접근성 정량 측정은 포함하지 않았습니다.
- 출처: 사용자가 OpenAI Astra 모델로 직접 진단해 세션에 첨부한 보고서 원문(2026-09-30). 이 세션에서 반영한 항목과 반영하지 않은 항목은 `docs/harness/handoff.md`의 2026-09-30 항목을 참고.

## 종합 의견

**시각적 통일성은 갖췄지만, 고객이 서비스 내용을 이해하고 문의·구매를 결정하는 데 필요한 정보가 부족합니다.**

디자인을 전면 교체하기보다 **서비스 명칭 → 첫 화면 메시지 → 구체적인 제공 내용 → 신청 경로** 순서로 개선하는 것이 효과적입니다.

특히 **‘외부 기술기획실’은 보조 설명으로는 사용할 수 있지만, 현재 Advisory의 대표 서비스명으로는 추천하지 않습니다.** 현재 공개된 서비스 범위에는 ‘IT 인프라·보안 자문’이 더 정확합니다.

이 문서의 수정 문구와 구성안은 제안입니다. 전문가 참여, 제공 결과물, 무료 지원 범위, 교육 운영, 구독 서비스 등에 관한 약속은 실제 제공 가능한 수준을 확인한 뒤 적용해야 합니다.

## 1. 먼저 수정해야 할 핵심 사항

| 우선순위 | 실제 확인한 사항 | UX 관점의 문제 | 개선 방향 |
|---|---|---|---|
| 최우선 | 상담·무료 진단·맞춤 추천 버튼 대부분이 `mailto:` 방식 | 이메일 앱 설정에 따라 문의가 번거롭고, 사이트 안에서 신청 완료를 확인하기 어려움 | 간단한 문의 폼을 기본으로 제공하고 이메일은 보조 수단으로 배치 |
| 최우선 | 하단 소개·채용·문의하기·이용약관·개인정보처리방침 링크가 `#`로 연결 | 클릭해도 기대한 정보가 나오지 않아 미완성 인상을 줌 | 실제 페이지 연결. 준비되지 않은 메뉴는 숨김 |
| 최우선 | Wellness의 ‘1분 체크리스트’ 안내 아래 버튼은 스마트스토어 구매로 연결 | 추천을 기대했는데 쇼핑 페이지로 이동하는 기대 불일치 | 체크리스트를 구현하거나 안내를 ‘제품 살펴보기’로 변경 |
| 높음 | 홈에 전문가·바이오 데이터·알고리즘·대규모 테크 기업 경력 등을 강조 | 이를 뒷받침하는 소개나 근거가 부족함 | 실제 제공·입증 가능한 내용만 남기고 프로필·방법·사례 제시 |
| 높음 | 서비스보다 ‘연결’·‘방법론’ 설명이 먼저 등장 | 방문자가 자신에게 필요한 서비스인지 빨리 판단하기 어려움 | 첫 화면 바로 아래에 서비스 선택 카드 배치 |
| 높음 | 과정·서비스·제품 목록이 모두 ‘예시’ 중심 | 문의 전에 비교하고 판단할 정보가 부족함 | 현재 이용 가능한 항목과 준비 중인 항목을 구분 |

## 2. ‘외부 기술기획실’ 명칭 검토

### 2.1 판단

**의도는 좋지만, 고객이 이해하는 범위와 실제 서비스 범위가 어긋날 수 있습니다.**

‘외부 기술기획실’에는 지속적으로 회사의 기술 의사결정을 지원한다는 장점이 있습니다. 그러나 처음 방문한 고객은 다음과 같은 의문을 가질 수 있습니다.

- **기술:** 제품 개발, 소프트웨어 개발, R&D까지 담당하는가?
- **기획실:** 전략과 보고서만 제공하고 구축·개선은 지원하지 않는가?
- **외부 조직:** 상주하는가? 운영을 대행하는가? 장애 대응까지 책임지는가?

현재 Advisory에 제시된 서비스는 인프라 진단·설계, 보안 체계, 규정·인증 대응 준비, 클라우드 전환, 솔루션 선정, 지속 자문입니다. 이 범위를 이름에서 직접 전달하는 편이 좋습니다.

### 2.2 후보 명칭 비교

| 표현 | 평가 | 적합한 위치 |
|---|---|---|
| 외부 기술기획실 | 기억에는 남지만 범위가 모호함 | 서비스 철학을 설명하는 보조 문구 |
| 외부 IT기획실 | ‘기술’보다 명확하지만 보안·실행 지원이 잘 드러나지 않음 | IT 투자·전략 수립이 중심일 때 |
| **IT 인프라·보안 자문** | 현재 서비스와 가장 직접적으로 일치 | **메뉴·서비스명** |
| **우리 회사의 IT·보안 파트너** | 비전문가도 이해하기 쉽고 지속 관계를 전달 | **첫 화면 핵심 문구** |
| 외부 CTO·CISO | 역할과 책임을 크게 기대하게 만듦 | 실제 계약 범위가 해당 역할에 부합할 때만 사용 |

### 2.3 권장 조합

| 요소 | 추천 문구 |
|---|---|
| 브랜드명 | ConnectX Advisory |
| 서비스 설명 | **IT 인프라·보안 자문** |
| 메인 타이틀 | **우리 회사에 맞는 IT 인프라와 보안, 함께 설계합니다.** |
| 설명 | 전담 인력이 부족하거나 중요한 IT 결정을 앞두고 계신가요? 현재 환경을 점검하고, 예산과 운영 여건에 맞는 개선 계획부터 실행까지 지원합니다. |
| 기본 버튼 | IT·보안 상담 신청 |
| 보조 버튼 | 제공 서비스 보기 |

‘외부 기술기획실’의 의미를 살리고 싶다면 본문에 다음과 같이 보조적으로 표현할 수 있습니다.

> 필요할 때 함께 검토하고 의사결정을 돕는, 우리 회사의 외부 IT기획실처럼 일합니다.

고객 대상도 ‘전담 책임자가 없는 기업’에만 한정하지 말고, **담당자는 있지만 인력이나 전문성이 부족한 기업**까지 포함하는 것이 자연스럽습니다.

## 3. 전체 홈페이지 구성 검토

### 3.1 현재 구조의 문제

홈에서 방법론을 설명하고, 세 가지 서비스를 소개한 다음, 다시 각 서비스를 길게 설명합니다. 방문자가 서비스 선택까지 도달하기 전에 읽어야 할 내용이 많습니다.

IT 자문을 찾는 기업 담당자와 영양제를 구매하려는 개인은 방문 목적이 다릅니다. 하나의 브랜드로 운영하되 홈에서는 각자의 목적지로 빠르게 안내해야 합니다.

### 3.2 권장 정보 순서

| 순서 | 구성 | 방문자가 얻어야 할 답 |
|---|---|---|
| 1 | 핵심 소개와 서비스 선택 | 무엇을 하는 회사인가? |
| 2 | 교육 / IT·보안 자문 / 건강기능식품 카드 | 내가 필요한 것은 어디에 있는가? |
| 3 | 서비스별 대표 제공 내용 | 구체적으로 무엇을 받을 수 있는가? |
| 4 | 담당자 소개·사례·운영 기준 | 왜 믿고 맡길 수 있는가? |
| 5 | 이용 절차 | 어떻게 시작하고 진행되는가? |
| 6 | FAQ와 문의 | 마지막으로 궁금한 점은 무엇인가? |

‘기술적 연동 모델’, ‘ConnectX Platform’은 통합 계정·데이터 연동·관리 기능 등을 갖춘 플랫폼을 기대하게 만듭니다. 실제로 그런 기능을 제공하지 않는다면 **‘ConnectX의 세 가지 서비스’**로 표현하는 편이 정확합니다.

### 3.3 메뉴 개선

| 현재 | 추천 |
|---|---|
| Academy | IT 실무교육 |
| Advisory | IT·보안 자문 |
| Wellness | 건강기능식품 |
| 상담 신청 | 문의하기 |

영문 브랜드는 각 페이지 안에서 유지합니다. 병기할 경우 ‘IT·보안 자문 Advisory’처럼 한국어 의미를 먼저 보여주는 것을 권합니다.

## 4. 홈 페이지 문구 수정 의견

‘연결이 만드는 변화’는 브랜드 슬로건으로 유지할 수 있습니다. 다만 그것만으로는 서비스가 드러나지 않으므로, 바로 아래 설명을 구체화해야 합니다.

| 현재 문구·요소 | 검토 의견 | 추천 방향 |
|---|---|---|
| 연결이 만드는 변화 | 슬로건으로 유지 가능 | 아래에 ‘IT 실무교육·인프라 및 보안 자문·건강기능식품 선택을 돕는 ConnectX입니다.’ 추가 |
| 우리의 방법론 | 공급자 관점의 제목이며 서비스보다 먼저 나옴 | 서비스 소개 뒤로 이동하고 ‘이렇게 함께합니다’로 변경 |
| 세 가지 연결 | 실제 서비스가 무엇인지 제목만으로 알기 어려움 | ‘필요한 서비스를 선택하세요’ |
| 지식·실무·사람 연결 | 교육 내용이 간접적으로 전달됨 | ‘현업에 적용하는 IT 실무교육’ |
| 기업 문제·기술·솔루션 연결 | 자문 범위가 추상적임 | ‘기업을 위한 IT 인프라·보안 자문’ |
| 건강·전문가·데이터 연결 | 실제 전문가·데이터 활용 여부 확인 필요 | ‘선택 기준을 안내하는 건강기능식품’ |
| 지금 연결을 시작하세요 | 버튼을 누른 뒤 무엇이 일어나는지 불명확함 | ‘필요한 서비스가 궁금하신가요?’ |

홈 첫 화면에서는 **‘서비스 둘러보기’를 주 버튼**, ‘문의하기’를 보조 버튼으로 두는 것을 권합니다. 서로 다른 목적으로 들어온 방문자에게 곧바로 ‘무료 진단’을 제안하면 무엇을 진단하는지 모호합니다.

첫 화면 하단 도식은 **Academy / ConnectX Platform / Wellness**로 보입니다. 상단 메뉴에는 Advisory가 있지만 이 도식에는 없어 구조가 일치하지 않습니다. 도식을 유지한다면 **Academy / Advisory / Wellness**를 동등하게 보여주는 것이 좋습니다.

## 5. Academy 페이지 검토

### 5.1 핵심 문제

**교육의 가치는 설명하지만, 어떤 교육을 언제 어떻게 받을 수 있는지는 판단하기 어렵습니다.**

| 항목 | 현재 문제 | 수정 제안 |
|---|---|---|
| 메인 타이틀 | ‘ConnectX Academy’가 가장 크게 표시됨 | 브랜드명은 작게, ‘현업에 바로 적용하는 IT 인프라·보안 교육’을 크게 |
| 소개 문구 | ‘자격증이 아니라’라는 표현이 자격증을 준비하는 방문자와 거리를 만들 수 있음 | ‘기초 개념부터 실제 운영·장애 대응까지, 실습으로 배우는 IT 교육’ |
| 커리큘럼 버튼 | 클릭 후 과정명과 한 줄 설명만 확인 가능 | 상세 커리큘럼을 제공하거나 ‘교육 분야 보기’로 변경 |
| 개인·기업 대상 | 서로 다른 문의 목적이 한 화면에 섞임 | ‘개인 교육 문의’와 ‘기업 맞춤교육 문의’로 경로 분리 |
| 수료 후 네트워크 | 구체적으로 무엇을 지원하는지 불명확 | 커뮤니티, 질의응답, 후속 학습 등 실제 지원 범위 명시 |

### 5.2 과정 카드에 필요한 정보

- 교육 대상
- 선수 지식
- 배우는 내용
- 교육 시간
- 진행 방식
- 일정 또는 개설 조건
- 비용 또는 견적 기준

정규 과정과 일정이 확정되지 않았다면 ‘아카데미 수강 신청’처럼 보이게 하기보다 **‘기업 맞춤교육·실무 강의’ 중심으로 안내**하는 편이 현재 운영 상태와 잘 맞습니다.

홈에 있는 ‘책에서 배울 수 없습니다’, ‘현업 탑클래스’, ‘수료 후 독점 네트워크’는 강조의 강도에 비해 근거가 부족합니다. **실습 주제와 강사 경력을 구체적으로 보여주는 편이 더 설득력 있습니다.**

## 6. Advisory 페이지 검토

### 6.1 유지할 강점과 보완점

세 페이지 중 고객의 문제를 가장 구체적으로 짚고 있습니다. ‘겸임 담당자’, ‘솔루션 선택의 어려움’, ‘인프라와 보안의 분리 대응’은 유지할 만한 내용입니다.

반면 **상담 후 무엇을 받는지, 어디까지 지원하는지**를 보강해야 합니다.

| 현재 항목 | 고객이 궁금해할 내용 | 추가할 정보 예시 |
|---|---|---|
| 인프라 아키텍처 진단/설계 | 결과물이 무엇인가요? | 현황 분석, 주요 문제 목록, 개선 구성도 |
| 보안 체계 수립 | 어떤 문서를 만들어 주나요? | 정책·지침, 점검표, 역할과 책임 정리 |
| 컴플라이언스 대응 지원 | 어떤 규정·인증까지 가능한가요? | 실제 지원 가능한 대상과 준비 범위 |
| 솔루션/벤더 선정 자문 | 견적 비교도 해주나요? | 요구사항 정의, 비교표, 평가 기준 |
| 상시 자문 | 얼마나 자주, 어떻게 연락하나요? | 월 회의 횟수, 문의 채널, 응답 기준, 포함 시간 |

위 항목은 게시할 정보의 예시입니다. 실제 제공 가능한 범위로 확정해야 합니다.

### 6.2 서비스 이용 방식 구분

| 이용 방식 | 설명 |
|---|---|
| 현황 진단 | 현재 문제와 개선 우선순위 확인 |
| 개선 프로젝트 | 합의한 범위의 설계·구축·정책 수립 지원 |
| 정기 자문 | 정기 점검과 IT·보안 의사결정 지원 |

‘리테이너’는 첫 등장에 **‘월 정기 자문’**으로 풀어 쓰는 것을 권합니다. ‘상시 자문’이나 ‘지속 모니터링’은 24시간 대응·관제를 기대하게 만들 수 있으므로 실제 운영 시간을 함께 제시해야 합니다.

### 6.3 무료 진단 범위 명확화

홈 FAQ에는 **‘진단 및 기획 초기 1단계 과정은 완전 무료’**라고 되어 있습니다. 이는 무료 상담보다 큰 약속입니다.

무료 범위가 인터뷰인지, 문서 검토인지, 실제 시스템 점검인지 구분해야 합니다. 유료 서비스로 전환되는 시점과 별도 견적 대상도 실제 운영 기준에 맞춰 안내하는 것이 좋습니다.

## 7. Wellness 페이지 검토

### 7.1 핵심 문제

**실제 판매 서비스와 현재 문구가 만들어내는 기대를 맞추는 작업이 가장 시급합니다.**

홈에서는 유전적 건강 데이터, 바이오 데이터 모델링, 의학·영양학 전문가 상담, 추천 알고리즘, 정기 모니터링을 설명합니다. 그러나 공개된 이용 경로는 이메일 문의와 스마트스토어 이동입니다.

이 기능들이 실제 운영되고 있다면 방법과 담당 전문가를 설명해야 합니다. 준비 단계라면 현재 이용 가능한 상품 안내·판매 중심으로 표현하는 편이 신뢰에 도움이 됩니다. 이는 공개 화면에 나타난 정보와 이용 경로를 비교한 UX 판단이며, 내부 운영 여부를 확인한 결과는 아닙니다.

### 7.2 문구 수정 제안

| 현재 문구 | UX 관점의 문제 | 추천 문구·방향 |
|---|---|---|
| 건강기능식품 위탁판매 | 고객 혜택보다 내부 유통 방식을 앞세움 | ‘건강기능식품 셀렉션’ 또는 ‘건강기능식품 구매 가이드’ |
| 나에게 맞는 영양제를 정확하게 찾아드립니다 | 개인 적합성을 확정적으로 판단한다는 기대 | ‘제품 정보를 비교하고 선택할 수 있도록 돕습니다’ |
| 영양제, 아무거나 드시고 계신가요 | 방문자의 선택을 부정적으로 평가하는 느낌 | ‘영양제, 어떤 기준으로 선택하시나요?’ |
| 진짜 처방 패키지 | 전문적인 진료·처방 서비스를 연상시킴 | 실제 서비스에 맞춰 ‘제품 구성 안내’ 등으로 변경 |
| 전문가가 검수한 제품만 소개합니다 | 전문가와 검수 기준이 보이지 않음 | 실제 검수자·기준을 공개하거나 확인 가능한 선정 기준으로 대체 |
| 1분 체크리스트로 시작합니다 | 해당 위치에서 체크리스트를 시작할 수 없음 | 체크리스트 구현 전에는 삭제 |

### 7.3 스마트스토어 구매 중심의 첫 화면 제안

| 요소 | 추천 |
|---|---|
| 타이틀 | **나와 가족을 위한 건강기능식품, 선택 기준부터 꼼꼼하게.** |
| 설명 | 브랜드, 제품 정보, 소비기한과 구매 조건을 확인하고 비교해 보세요. |
| 주 버튼 | 스마트스토어에서 제품 보기 |
| 보조 버튼 | 제품 문의하기 |

제품 선정 기준도 추상적인 ‘검증된 제품’보다 **어떤 정보를 어떻게 확인하는지** 보여주는 것이 좋습니다. 브랜드·판매 구성·표시 정보·잔여 소비기한 안내 기준 등 실제 관리하는 항목을 제시합니다.

정기구독을 운영한다면 상담 유도만 하기보다 배송 주기, 결제 방식, 변경·해지 방법을 확인할 수 있어야 합니다.

## 8. 시각 디자인과 공통 문장 개선

### 8.1 시각 디자인

짙은 남색과 청록색, 카드 형태, 여백의 사용은 일관되어 있습니다. 다만 읽기와 정보 선택 측면에서는 다음 조정이 필요합니다.

| 항목 | 관찰 | 개선 방향 |
|---|---|---|
| 홈 배경 | 밝은 네트워크 선이 설명문 뒤에 겹침 | 본문 뒤 배경을 더 어둡게 하거나 그래픽 강도 축소 |
| 본문 가독성 | 어두운 배경 위 회색 문장이 시각적으로 약함 | 본문 밝기와 크기를 조정하고 실제 대비 측정 |
| 한국어 줄바꿈 | ‘연결하/여’, ‘인프라/보안’ 등이 어색하게 분리됨 | 단어 단위 줄바꿈과 문장 길이 조정 |
| 제목의 우선순위 | 영문 브랜드명이 크게, 고객 혜택은 작게 나옴 | 한국어 서비스·혜택을 주 제목으로 배치 |
| 상세 페이지 하단 | 페이지별 신청 영역 다음에 공통 상담 영역이 반복됨 | 해당 페이지에 맞는 신청 영역 하나로 통합 |
| Wellness 분위기 | IT 서비스와 동일한 어두운 화면 | 공통 브랜드는 유지하되 제품·소비자 정보 영역은 밝은 배경 검토 |

### 8.2 공통 표현 수정

과한 단정이나 번역투를 줄이면 더 전문적으로 읽힙니다.

| 현재 표현 | 권장 표현 |
|---|---|
| 전담 보안/인프라 책임자가 없이도 | 전담 인프라·보안 책임자가 없어도 |
| 최고 수준의 CTO, CISO를 고용하는 것은 불가능에 가깝습니다 | 전담 IT·보안 책임자를 채용하기 부담스러운 기업을 위해 |
| 리스크를 원천 제거합니다 | 주요 위험을 파악하고 줄입니다 |
| 시장의 죽은 이론 | 실제 운영 환경에서 활용하는 지식 |
| 완전히 보살핌 받는 비즈니스 환경 | 안정적으로 운영하고 성장할 수 있는 환경 |
| 지치지 않고 지속될 수 있도록 | 개선 효과가 지속되도록 |

### 8.3 브라우저 페이지 타이틀 제안

현재 탭 제목은 브랜드 중심입니다. 페이지의 실제 내용을 함께 넣는 것을 권합니다.

| 페이지 | 추천 페이지 타이틀 |
|---|---|
| 홈 | ConnectX \| IT 실무교육·인프라 및 보안 자문·건강기능식품 |
| Academy | IT 인프라·보안 실무교육 \| ConnectX Academy |
| Advisory | 기업 IT 인프라·보안 자문 \| ConnectX Advisory |
| Wellness | 건강기능식품 셀렉션 \| ConnectX Wellness |

## 9. 실행 순서와 검증

| 단계 | 실행 내용 | 완료 기준 |
|---|---|---|
| 1. 신청 경로 정리 | 문의 폼, 실제 연락처, 작동하지 않는 하단 링크 수정 | 각 버튼이 설명한 목적지로 연결되고 문의 완료를 확인할 수 있음 |
| 2. 서비스 약속 정리 | 무료 범위, 운영 중인 서비스, 전문가·데이터 활용 여부 점검 | 현재 제공하는 서비스와 준비 중인 서비스를 구분하고 근거를 제시함 |
| 3. 제목과 메뉴 수정 | 한국어 서비스명을 앞세우고 Advisory를 ‘IT 인프라·보안 자문’으로 명확화 | 첫 화면에서 서비스 종류와 고객 대상을 이해할 수 있음 |
| 4. 의사결정 정보 보강 | 교육 세부 정보, 자문 결과물·계약 범위, 실제 제품과 구매 조건 추가 | 고객이 문의 전에 서비스 적합성을 판단할 수 있음 |
| 5. 시각 개선과 검증 | 가독성·줄바꿈·모바일 화면 점검 및 전환 지표 확인 | 주요 화면과 신청 경로의 불편을 확인하고 수정함 |

개선 후에는 서비스 클릭률, 문의 완료율, 스마트스토어 이동률을 확인합니다. 실제 효과는 방문자와 전환 데이터를 통해 판단해야 하며, 이번 검토만으로 전환율 상승 폭이나 매출 효과를 확정할 수는 없습니다.

**우선 투자할 부분은 새로운 이미지 제작보다 ‘무엇을 제공하는지 명확한 설명’과 ‘막힘없이 신청할 수 있는 경로’입니다.** 현재 홈페이지에서는 이 두 가지를 개선하는 것이 고객의 이해와 문의 전환에 가장 직접적으로 도움이 될 것으로 판단합니다.
