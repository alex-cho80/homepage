# 시너지 루프 — Academy/Advisory/Wellness 연결 서사

배경: 사용자가 `ConnectX_사업계획서_v2.pdf`(Wellness 위탁판매 사업계획서)를 공유하며,
현재 홈페이지에서 세 사업(Academy/Advisory/Wellness)이 서로 무관해 보인다고 지적.
사업계획서 안에는 실제로 연결 논리가 있었으나 홈페이지에 반영돼 있지 않았음.

## 사업계획서에서 찾은 연결 논리

1. **현재 사실 (검증 가능)** — Ⅰ-2(진입 세그먼트), Ⅲ-3(독점 전략 Step 1):
   Wellness의 1차 타깃(3040 IT·사무직 직장인)은 "ConnectX 대표의 IT 커뮤니티·강의
   접점과 직결"된다고 명시 — 즉 Academy 수강생·Advisory 고객사 임직원과 겹치도록
   의도적으로 설계된 타깃. 지금 당장 사실로 말해도 되는 연결고리.
2. **장기 지향 (3단계, 미래)** — Ⅲ-2(Four Pillars) ②④, SWOT(Ⅱ-5):
   Advisory의 보안·개인정보 거버넌스 역량이 Wellness의 민감정보(검진 결과 등) 처리
   핵심 해자로 지목됨 ("ConnectX 보안 컨설팅 사업의 의료기관 접점과 연계"). 단,
   사업계획서 자체가 이를 "3년차 이후" 지향점으로 명시 — 현재 사실처럼 쓰면 과장.

## 결정 (사용자 확인 완료 — 둘 다 반영)

홈페이지에 새 섹션(`LoopSection`)을 Bento/서비스 하이라이트 뒤, Trust 섹션 앞에 추가:

- **현재 사실 블록** (3단계 카드, 일반 카드 스타일): Academy → Advisory → Wellness
  순서로 "같은 사람·같은 신뢰에서 출발"한다는 서사. 문구는 사업계획서 Ⅰ-2/Ⅲ-3의
  타깃 중첩 논리를 그대로 반영.
- **지향점 블록** (점선 테두리로 시각적으로 구분, "앞으로의 방향" 라벨): Advisory의
  보안/개인정보 역량이 장기적으로 Wellness의 건강 데이터 보호로 확장된다는 서사.
  "장기적으로는", "확장할 계획입니다" 등 명시적 미래형 표현 사용 — 콘텐츠 갭 처리
  원칙(decisions.md 2026-10-01)과 동일하게 현재/비전을 명확히 분리.

적용 범위는 홈페이지(`app/page.tsx`)로 한정 — 사용자 지적이 홈페이지 대상이었고,
각 상세 페이지(Academy/Advisory/Wellness)는 이번 범위에서 손대지 않음.
