# ConnectX Advisory — `/advisory` 페이지 기획

## 대상 페이지

`/advisory` (ConnectX Advisory 브랜드 유닛 상세 페이지)

## 목적

- 전담 인프라/보안 책임자를 두기 어려운 중소기업(SMB)의 의사결정권자
  (대표, 경영지원/총무 담당자 등 IT를 겸임하는 사람)에게 Advisory가
  "외부 기술기획실"로서 신뢰할 수 있는 파트너임을 설득하고 상담 신청으로
  전환시킨다.
- B2B 컨설팅은 구매 사이클이 길고 신뢰 문턱이 높은 영역이므로, 이 페이지는
  사이트 전체에서 가장 신뢰/전문성 신호(포지셔닝 문구, 프로세스, 실적)를
  촘촘히 배치해야 하는 페이지다. decisions.md에서 사이트 전체 톤앤매너의
  기준점으로 Advisory의 B2B 포지셔닝을 명시한 것도 같은 맥락.

## 핵심 메시지

**"인프라와 보안을 따로 보지 않는, 우리 회사의 외부 기술기획실."**

- Position: **SMB Infra & Security Transformation Partner**
  - 전담 인프라·보안 책임자를 채용하기 어려운 기업의 외부 전문팀
  - 기업의 IT 인프라와 보안을 함께 보는 외부 기술기획실
- 3개 연결 축 (connect phrase 확장):
  1. **기업 문제**: 예산·인력 제약 속에서 실제로 겪는 인프라/보안 문제
  2. **기술**: 그 문제에 맞는 기술적 진단과 아키텍처 판단
  3. **솔루션**: 실행 가능한 솔루션·벤더·체계로 연결
- 랜딩 페이지 카드에 이미 position/positionDetails 두 줄이 노출되므로, 이
  페이지는 그 두 줄을 "왜 그런 포지션인지 / 실제로 무엇을 해주는지"로
  풀어내는 역할을 한다 — 카드 문구를 그대로 반복하지 않는다.

## 정보구조 (섹션 순서)

1. Hero
2. Position 상세 설명 (외부 전문팀 / 외부 기술기획실)
3. 문제 제기 — SMB가 인프라/보안에서 흔히 겪는 어려움
4. Advisory가 연결하는 것 (기업 문제ㆍ기술ㆍ솔루션 3축)
5. 서비스 프로세스 — ConnectX 4단계를 컨설팅에 적용
6. 서비스 영역
7. 신뢰 요소 (팀/방법론/실적)
8. FAQ
9. CTA — 무료 진단/상담 신청

## 섹션별 카피 초안

### 1. Hero

- 상단 라벨: `인프라/보안 컨설팅`
- 타이틀: **ConnectX Advisory**
- Position 배지: `SMB Infra & Security Transformation Partner`
- 서브 카피: "기업 문제ㆍ기술ㆍ솔루션을 연결해, 전담 인프라·보안 책임자
  없이도 안전하게 성장할 수 있게 합니다."
- CTA: `[무료 진단 신청]` / `[서비스 영역 보기]`

### 2. Position 상세 설명

- 소제목: "왜 '외부 기술기획실'인가"
- 바디 카피:
  - "많은 중소기업은 인프라와 보안을 각각 채용하거나, 아예 겸임으로
    떠안습니다. 그 결과 문제가 생기기 전까지는 아무도 전체 그림을 보지
    못합니다."
  - "Advisory는 그 자리를 대신 채웁니다. 전담 인프라·보안 책임자를
    채용하기 어려운 기업을 위한 **외부 전문팀**으로, 인프라와 보안을 따로
    보지 않고 **외부 기술기획실**처럼 함께 봅니다."
- 이 두 문장(외부 전문팀 / 외부 기술기획실)은 `lib/brand-units.ts`의
  positionDetails 원문을 그대로 살리되, 랜딩 카드보다 한 단계 더 설명을
  붙인 버전. 원문 자체는 변경하지 않는다.

### 3. 문제 제기

- 소제목: "이런 고민, 익숙하신가요"
- 리스트(카드형, 3~4개):
  - "IT 인프라 담당자가 한 명뿐이거나, 다른 업무와 겸임하고 있다."
  - "보안 사고가 나야만 보안을 생각하게 된다 — 사전 점검 체계가 없다."
  - "클라우드/솔루션 도입을 검토 중인데, 무엇이 우리 규모에 맞는지 판단할
    사람이 없다."
  - "인프라 이슈와 보안 이슈가 따로따로 대응되어, 전체 리스크가 안 보인다."

### 4. Advisory가 연결하는 것

- 소제목: "기업 문제ㆍ기술ㆍ솔루션을 연결합니다"
- 3열 카드:
  - **기업 문제 연결**: "예산, 인력, 업종 특성까지 고려해 우리 회사가
    실제로 겪는 문제를 먼저 정확히 정의합니다."
  - **기술 연결**: "정의된 문제에 맞는 인프라/보안 기술과 아키텍처 판단을
    제공합니다. 유행이 아니라 규모에 맞는 기술."
  - **솔루션 연결**: "판단에서 끝나지 않고, 실제로 도입 가능한 솔루션·
    벤더·운영 체계로 연결해 실행까지 이어갑니다."

### 5. 서비스 프로세스 (마스터 브랜드 4단계 적용)

- 소제목: "진단 → 큐레이션/설계 → 실행 → 지속관리"
- 4단계 카피:
  1. **진단**: "현재 인프라/보안 현황을 점검하고 리스크를 진단합니다."
  2. **큐레이션/설계**: "기업 규모와 예산에 맞는 개선 우선순위와 아키텍처를
     설계합니다."
  3. **실행**: "구축/이행을 직접 지원하거나, 내부 인력과 함께 실행합니다."
  4. **지속관리**: "1회성 컨설팅으로 끝내지 않고, 외부 기술기획실처럼
     지속적으로 모니터링·리테이너 형태로 함께합니다." (이 문장이 "외부
     기술기획실" 포지션을 프로세스 단에서 다시 증명하는 역할)

### 6. 서비스 영역

- 소제목: "무엇을 함께 보나요"
- **[콘텐츠 갭 — 확인 필요]** 구체적 서비스 상품/패키지명은 사업 자료
  없음. 도메인("인프라/보안 컨설팅")과 Position 설명에서 유추 가능한
  영역을 예시로 제안:
  - 인프라 아키텍처 진단/설계, 보안 체계 수립(정책·프로세스), 컴플라이언스
    대응 지원, 클라우드 전환 자문, 솔루션/벤더 선정 자문, 상시 자문
    (리테이너)
- 개발 시 이 섹션은 카드 그리드로 구현하되 실제 상품명 확정 전까지는
  위 예시를 placeholder로 사용.

### 7. 신뢰 요소

- 소제목: "왜 Advisory인가"
- **[콘텐츠 갭 — 확인 필요]** 실제 팀 경력, 고객사, 프로젝트 실적 데이터
  없음. B2B 컨설팅은 신뢰 요소(레퍼런스, 자격, 방법론)가 전환에 결정적이므로
  이 섹션은 다음 스펙에서 반드시 실데이터로 채워야 한다. placeholder 카피:
  - "인프라와 보안을 함께 보는 팀" / "기업 규모에 맞는 현실적인 제안"
    / "1회성이 아닌 지속 관리"
- 실적/고객사 로고/후기가 없는 초기 단계라면, 대안으로 "무료 진단"을 낮은
  진입장벽으로 전면에 내세우는 것을 제안 (9번 CTA와 연결).

### 8. FAQ

- 예시 질문:
  - "정규 인력 채용 대신 Advisory를 쓰면 무엇이 다른가요?"
  - "우리 회사 규모가 작은데도 대응이 되나요?" (SMB 타깃 명시적으로 안심시키는 질문)
  - "일회성 컨설팅인가요, 지속적인 관리인가요?"
  - "인프라와 보안을 각각 따로 의뢰할 수도 있나요?"

### 9. CTA

- 소제목: "지금 무료로 진단받아보세요"
- 바디: "전담 책임자가 없어도 괜찮습니다. 지금 상태를 먼저 함께
  점검해드립니다."
- 버튼: `[무료 진단 신청]` / 보조 링크: `[담당자와 상담 예약]`

## 톤앤매너 메모

- decisions.md에 명시된 사이트 전체 기본 톤(전문적/신뢰감 우선)이 바로 이
  Advisory 포지셔닝에서 나온 기준이므로, 이 페이지는 그 톤을 가장 엄격하게
  지킨다 — 가벼운 유머, 이모지, 캐주얼한 구어체 지양.
- "외부 기술기획실"이라는 포지션 문구는 반복 노출(Hero 배지 → 2번 섹션
  → 5번 프로세스 4단계 → FAQ)해 각인시키는 것을 의도적으로 설계했다.
- SMB 타깃임을 잊지 않도록, "대기업 수준의" 같은 표현보다 "우리 규모에
  맞는", "무리 없이" 같은 현실적 어휘를 쓴다.
- 신뢰 요소(7번 섹션)와 서비스 영역(6번 섹션)은 실데이터 공백이 가장 큰
  섹션이다. 카피가 과장된 약속(구체적 수치, 확정되지 않은 고객사명 등)을
  만들어내지 않도록 다음 스펙에서 사업 담당자 확인이 반드시 필요하다는 점을
  개발팀에 전달.
